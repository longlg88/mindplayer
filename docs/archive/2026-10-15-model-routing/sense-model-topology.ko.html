Sense 자체는 무엇을 구현하는가

의미 판정과 모델 적용은 다른 책임입니다.

Jev에서 참고하는 부분은 자연어와 상태를 좁은 구조화 판단으로 바꾸는 역할입니다. Sense의 판정기는 입력·최근 대화 맥락을 보고 작업 유형, 추론 요구, 변경 위험, 맥락 의존도를 반환합니다. 일반 에이전트처럼 계획이나 답변을 생성하지 않습니다.

정책 코드는 이 판단과 해당 제공자의 모델별 측정 프로파일을 결합해 모델 ID를 결정합니다. 모델 목록은 런타임에서 발견하되, 목록에 있다는 사실만으로 계정의 실행 권한을 보장하지 않습니다. 계정 정책·지원 입력·검증된 설정·최근 거부 정보를 함께 봅니다.

배치와 언어

실행부는 Rust로 MindPlayer 안에 둡니다. TUI를 막지 않도록 백그라운드 작업과 창별 큐를 씁니다. 서비스마다 별도 HTTP 서버를 만들지 않습니다.

자체 판정모델의 학습·평가는 Python으로 분리합니다. 추론 라이브러리와 모델 파일 형식은 실제 성능 검증 전까지 미정입니다. 현재 학습된 Sense 모델은 없습니다.

모델 이름 대신 능력을 판단

‘분석’이면 특정 모델이라는 고정 키워드 표를 제품 로직으로 쓰지 않습니다. 직전 지시, 변경 범위, 맥락 길이, 입력 형태도 판단에 포함합니다.

새 모델이 추가되면 카탈로그·성능 프로파일을 갱신합니다. 모델 이름이 바뀔 때마다 판정기를 재학습할 필요가 없도록 판단과 정책을 분리합니다.

아래 타입은 자체 서비스의 설계 계약입니다. 기존 API나 구현 완료된 코드가 아닙니다. 계정 인증정보·샌드박스 권한은 어댑터가 보유하며, 판정모델에 비밀값을 전달하지 않습니다.

현재 PTY는 키 입력 바이트를 전달합니다. 완성된 프롬프트를 안전하게 얻는 어댑터는 새 구현이 필요합니다. 같은 시각적 입력 영역의 소유권을 MindPlayer로 가져오는 제안이며, 현재 Codex CLI에 단순히 hook을 붙이면 된다고 주장하지 않습니다. 원래 CLI의 입력·첨부·승인 동작을 보존하는 것은 구현 검증 항목입니다.

목표 어댑터는 구조화된 제출과 app-server 실행·이벤트 렌더링을 소유합니다. 기존 CLI의 PTY와 app-server가 같은 대화를 동시에 실행하지 않습니다. 신규 창의 실행 소유권과 기존 threadId의 정확한 재개·단일 소유권 이전을 따로 검증해야 합니다. 메타데이터 조회 성공은 기존 창에 붙을 수 있다는 증명이 아닙니다.

판정 작업은 제공자·계정 참조·창 세대·threadId·활성 턴·입력·카탈로그 버전에 묶습니다. 승인, steer, 새 입력, 창 재생성·닫기·재식별 시 오래된 결과를 폐기합니다. 새 턴/steer의 구분은 입력 제어 이벤트가 담당하며 판정모델이 임의로 결정하지 않습니다.

최근 맥락은 같은 계정·대화의 필요한 턴만 포함하고 출처를 남깁니다. 같은 분류라는 이유로 다른 창의 대화를 합치지 않습니다. 판단 시간 예산·큐 상한·취소·역압 동작은 구현 전 결정하고 검증합니다. 대체 모델도 없으면 정상 오류 경로를 따르며, 성공한 척하거나 입력을 버리지 않습니다.

Sense의 추론 포트에 연결

REA는 분석 가능한 바이너리·JavaScript·실행 동작의 조사 도구입니다. 서비스의 실시간 입력 경로에는 들어가지 않습니다. 클라이언트 분석만으로 원격 Jev의 비공개 가중치·원래 신경망 구조·학습 파이프라인을 복구할 수 있다고 주장하지 않습니다.

첫 평가셋에는 한국어 표현 변화, 짧은 후속 요청, 긴 맥락, 단순 문구 수정, 다중 파일 분석, 높은 변경 위험, 입력 중 명령, 판정 실패를 포함합니다. 같은 입력을 여러 후보 모델로 평가해 성공 품질과 지연을 기록하고, 정책이 선택한 모델의 결과를 비교합니다.

범용 LLM의 구조화 출력은 초기 평가 기준선으로 비교할 수 있습니다. 이것을 학습된 자체 Jev와 같다고 부르지 않습니다. 학습/검증/최종 평가를 분리하고, 확률이 잘 보정되었는지 별도 검증합니다. 실제 사용자 원문을 자동으로 학습 수집하거나 외부 전송하지 않습니다.

배포 승인에 필요한 증거

  • IME·소프트 개행·붙여넣기·첨부·초기 대기 입력의 손실 없는 제출.
  • 새 턴·steer·승인 응답이 올바르게 구분됨.
  • 정확한 기존 threadId 재개·단일 실행 소유권·같은 계정과 권한 유지.
  • 중복 실행·다른 창 적용·전송 후 불명확 재시도가 없음.
