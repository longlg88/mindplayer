왜 이 UI인가 — 세 대안과 변경 범위
대안판단이유
기존 모델줄에 단계·모델 표시이 시안입력 위치와 대화 본문을 유지하고 현재 턴을 바로 확인합니다.
판단마다 대화에 상태 메시지 삽입제외실행 결과와 관리 메시지가 섞이고 대화가 길어집니다.
옆에 상시 라우팅 패널 추가제외새 조작과 화면 점유가 생깁니다. 사용자가 원한 자동 동작이 아닙니다.

새 모델 선택기·자동/고정 모드·서비스 활성화 버튼·설정창·매 입력 확인창은 없습니다. 기존 입력·모델줄·Ctrl-G Trace·도구 실행 승인·권한은 유지합니다. 집중 화면과 4+3 화면은 원래 보기 방식이며 새로운 분할을 추가한 것이 아닙니다.

시안과 실제 구현의 경계

이 문서는 UI 시안입니다. JavaScript는 미리 정한 화면만 바꿉니다. 실제 Jev 판정, 모델 선택·교체, Codex 실행, API 키 접근, 원격 요청을 하지 않습니다. 대화·모델·단계는 합성 예시입니다.

현재 0.55.5는 Jev 호출과 검증 코드가 있지만, 운영용 비교 근거가 없으면 기존 모델을 유지합니다. 위의 B→A→B 적용 화면은 아직 구현 완료가 아닙니다. 모델 A/B는 특정 모델의 성능·가격 순위를 뜻하지 않으며, 실제 후보는 계정에서 확인해야 합니다.

‘실행 확인’ 표시는 향후 검증된 실행 모델 증거가 있을 때만 허용하는 목표 상태입니다. 현재 네이티브 이벤트가 그 증거를 제공한다고 가정하지 않습니다. 증거가 없으면 ‘요청 · 실행 모델 미확인’을 유지합니다. 현재 턴 추가 지시와 queued 새 입력의 경계도 실제 통합에서 검증해야 합니다.

선택 실패의 ‘실행 보류’는 오류 UX 제안이며 이번 문서로 기존 fallback 동작을 변경하지 않습니다. 스크린샷의 Git 작업 폴더 오류와 중단 원인은 이 시안의 검증 범위가 아닙니다.

기준 화면·재현 가능한 검증

1차 확인: 사용자 집중 화면, 기존 DESIGN.md 및 4+3 UI 계약. 2차 대조: 실제 TUI의 집중/분할/사용량 footer·네이티브 입력 전달 경계와 기존 HTML 브라우저 검증. 사용자 원본 스크린샷과 실제 대화는 이 파일에 저장하지 않았습니다.

동작 구현이 아닌 브라우저 문서 검증: MINDPLAYER_PLAYWRIGHT_MODULE=/설치된/playwright node docs/tests/jev-turn-ui.test.cjs. 정상 10단계, 예외 4종, 후속 새 턴의 모델 예시, 같은 세션·계정·CWD, 키보드, 1440/969/390px, 4+3 및 전체 폭 footer, 외부 요청 0건을 검사합니다. 새 의존성은 설치하지 않습니다.
