What the UI must say

  • Codex/Claude is the session owner, not Jev's choice.
  • Jev's model contract is per-turn and inspectable.
  • Context sources are named, not implied.
  • Low confidence can pause or fall back safely.

What the UI must not say

  • Do not display hidden chain-of-thought as if it were evidence.
  • Do not silently move a prompt to another provider.
  • Do not create a new pane for every Jev decision.
  • Do not confuse idle, completed, and verified success.

Three implementation approaches

Decision scope: integrate Jev into the existing MindPlayer boundaries without turning Jev into a provider router.

ApproachHow it worksTrade-off
A · turn gate + structured transportIntercept submit, create Jev decision, then call Codex app-server or a Claude adapter for the already-selected pane.Best auditability; requires a structured path beside raw PTY.
B · PTY wrapperKeep raw PTY and inject Jev decisions before writing the submitted prompt.Small initial diff; fragile around interactive terminal state and model switching.
C · Jev daemon + pane bridgesRun Jev as a local process; MindPlayer talks to it over a typed local protocol and each pane has a provider bridge.Best long-term separation; adds process lifecycle and IPC work.

Design references and adopted conventions

The topology uses a C4-inspired container view: explicit element types, labeled one-way relationships, and a legend so the diagram stands alone. The UI uses native tabs, focusable controls, and disclosure-style progressive detail rather than keyboard shortcuts as the only access path.
