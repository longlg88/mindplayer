현재 요청

가능한 범위와 제안

기본은 A. 기존 PTY를 사용하면서 현재 요청의 실행 상태를 바로 확인합니다. 요청별 비교가 필요하면 C로 전환합니다.

실행 이벤트는 로컬 로그·hook에서 들어온 즉시 반영하고, 토큰은 provider usage가 도착했을 때 갱신합니다. 도착 전에는 집계 대기이며 0으로 간주하지 않습니다.

제안하는 진입 방식은 세션 상단의 관찰 토글 또는 MindPlayer 전용 명령 입력창입니다. :observe와 이 명령 입력창은 신규 구현 대상입니다. 현재 실행 중인 Codex·Claude 입력창에 이 문자열을 보내는 방식이 아닙니다.

OFF는 패널을 숨기는 동작입니다. 에이전트 실행과 이 데모의 진행은 계속됩니다. 세션별 표시 상태가 유지됩니다.

실제 구현: 선택 세션 로그 증분 읽기 → 세션·턴·도구 ID 연결 → 이벤트 중복 제거 → provider별 원본 usage 해석 → TUI 갱신. 토큰 지연·부분 기록·로그 회전을 처리해야 합니다.

TypeSafe / 실제 호출과 데모의 경계

TypeSafe는 공개 진행 메시지의 의미를 분류합니다. 도구 실행·사용량 집계는 코드가 수행합니다. 아래는 합성 메시지 3개를 분류한 실제 HTTP 응답 요약입니다.

실제 호출 증거 보기
HTTP 200 · model jev-1.13.0 · measured 664 ms
request_id: req_01a0bf69ea9473169124c03708991977
input_tokens: 641 / output_tokens: 129

"I will compare the account lookup paths and read the relevant code."
→ inspect (confidence 1.0)
"The patch is ready; running regression tests now."
→ verify (confidence 1.0)
"Still working."
→ unknown (confidence 1.0)

위 값은 TypeSafe 분류 요청 자체의 usage입니다. 화면에서 재생하는 코딩 세션의 예시 토큰과 별개이며, 계정 대시보드 반영은 확인하지 않았습니다. 브라우저에서 API를 호출하지 않습니다.

분류는 추론으로 표시하고, 모호한 메시지는 판단 불가로 남깁니다. 세 예제의 성공은 실제 로그에 대한 정확도 보장이 아닙니다. 제품 연동 시 외부 전송은 선택 기능으로 둡니다.
