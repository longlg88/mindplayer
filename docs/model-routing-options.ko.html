어떻게 모델을 바꿔 실행하나 — 세 안 모두 필요한 연결부

판정기를 고르는 것과, 현재 Codex 창의 모델을 바꾸는 것은 별개입니다. 지금 MindPlayer는 키보드 바이트를 CLI의 PTY로 전달합니다. 단순히 Enter를 감지하거나 /model을 대신 타이핑하는 것으로 완성된 통합을 보장할 수 없습니다.

  1. 완성된 입력같은 입력 영역에서 새 턴 제출을 명확히 구분
  2. 판정 + 코드 정책규칙 / 기존 LLM / 혼합으로 모델 후보 결정
  3. 허용 후보 검증계정·첨부·설정·측정된 작업 적합성 검사
  4. 새 턴 1회 실행같은 계정·threadId에 모델을 명시해서 제출

Codex app-server는 새 turn/start에서 모델을 지정할 수 있습니다. 진행 중인 턴의 turn/steer는 모델 변경을 받지 않습니다. 따라서 이 제안의 자동 선택 단위는 완성된 새 프롬프트이지 승인 응답이나 진행 중 추가 지시가 아닙니다. 공식 턴 시작·추가 지시 문서

기존 입력 위치는 유지하되 내부 제출 처리와 이벤트 렌더링은 개발해야 합니다. 기존 PTY와 app-server를 같은 대화의 동시 실행 주체로 붙이지 않습니다. 새 창의 단일 실행 소유권과 기존 대화의 정확한 재개를 각각 검증해야 합니다.

모델은 이름이 아니라 실제 후보 중에서

런타임 모델 목록과 계정 정책·지원 입력·검증된 설정으로 후보를 제한합니다. 목록이 있다는 사실만으로 실제 실행 권한이 증명되지는 않습니다. 후보가 하나면 바꾸지 않습니다. 모델별 속도·가격·품질 프로파일은 평가 후 정하고, 필요하면 지원되는 추론 강도를 별도 축으로 다룹니다. 공식 모델 목록 문서

A/B는 시연용 이름입니다. A가 저렴하거나 B가 언제나 더 낫다는 뜻이 아닙니다. Codex라는 실행 엔진·창·계정·대화는 고정합니다. Claude 등 다른 엔진의 지원은 별도 검증 전 약속하지 않습니다.

기존 CLI 인증 재사용·출력 스키마는 공식 비대화형 실행 문서, 로그인과 API 과금 구분은 공식 인증 문서에서 확인했습니다. 여기서 자격증명을 추출하거나 실제 판정을 실행한 것은 아닙니다.

직접 API 경로의 도구 선택·출력 형식은 Responses API 레퍼런스에 근거합니다. 구조화 출력은 형식 제약입니다. 선택의 정확도·권한·안전성을 대신 검증해 주지 않습니다.

작업은 한 번, 판정 추론은 추가될 수 있음

“기존 대화에서 작업 1회”는 판정까지 추론 한 번이라는 뜻이 아닙니다. 2안은 매번, 3안은 규칙으로 확정하지 못할 때 별도 판정이 있습니다. Vercel·Jev·PIM·자체 모델 학습은 이 세 안의 필수 구성요소가 아닙니다.

오판·지연·중복 실행은 어떻게 막나
  • 전송 전 판정 실패: 시간 초과·거절·형식 오류·맥락 부족이면 이미 사용 가능했던 기존 모델을 유지합니다. 그것도 사용할 수 없으면 기존 오류로 알립니다. 자동으로 더 약한 모델로 내리지 않습니다.
  • 전송 후 상태 불명: 모델을 바꿔 같은 작업을 다시 보내지 않습니다. 먼저 원래 턴의 상태를 확인합니다. 이 제안은 실패 후 자동 재실행·이중 실행 방식이 아닙니다.
  • 낡은 판단 차단: 창 세대·계정·threadId·입력 버전·모델 목록 버전에 판단을 묶습니다. 취소·입력 수정·창 재생성·계정 변경 시 무효화합니다. 큐 상한·역압·판정 시간 예산도 필요합니다.
  • 입력과 권한 유지: IME·붙여넣기·여러 줄·첨부·승인·추가 지시를 구분합니다. 모델 선택 확인창은 없애도 원래 도구 실행 승인·샌드박스는 유지합니다.
  • 판정 데이터 최소화: 같은 대화의 현재 입력과 필요한 최근 맥락만 사용합니다. 다른 창·계정 대화와 비밀값을 섞거나 원문을 자동 학습 자료로 저장하지 않습니다.
  • 표시의 진실성: 후보 → 요청 → 수락 → 실제 모델 관측을 구분합니다. 실행 증거가 없으면 요청 상태 또는 미확인으로 남깁니다. 이 문서도 ‘적용 완료’를 시연하지 않습니다.
내 의견 — 3안을 목표로 하되, 검증은 2안부터
  1. 실행 없이 판단을 비교합니다. 한국어·짧은 후속 지시·긴 맥락·첨부·고위험 변경의 자체 평가셋에서 2안을 기준으로 봅니다. 실제 사용자 원문을 무단 수집하지 않습니다.
  2. 맞았던 일부 사례만 규칙으로 옮깁니다. 3안이 판단 호출을 얼마나 줄이는지와 규칙 때문에 생긴 오선택을 같이 측정합니다. LLM의 자기 확신값을 검증된 정확도로 쓰지 않습니다.
  3. 전환 연결은 별도로 검증합니다. 같은 대화 유지, 완성 입력 경계, 단일 실행, 승인 보존, 취소·오래된 판단 차단을 통과한 뒤 실제 사용합니다.

비교할 지표는 작업 품질, 부적합 모델 선택률, 판정 포함 종단 지연, 추가 사용량·총비용, 실패 시 입력 보존입니다. 현재 정확도·속도·절감률은 측정하지 않았습니다. 품질이 확인되지 않으면 기존 모델 유지가 기본입니다.

제품의 최종 방식은 아직 선택되지 않았습니다. 이 HTML은 의견 비교와 정해진 시연만 제공하며, 실제 모델 선택 기능을 구현하지 않습니다.
