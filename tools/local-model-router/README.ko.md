# 로컬 Codex 모델 라우팅

로컬 수정본 MindPlayer에서 **기존 Codex 터미널 UI → 로컬 중계 → Codex
app-server** 경로를 사용합니다. 0.55.8은 매 새 사용자 턴에서 실제 Jev가 현재
카탈로그의 모델·추론 강도를 선택하고 그 값으로 실행을 요청합니다. PIM은 만들지 않습니다.
커밋·푸시·배포·상주 서비스 등록 없이 로컬 실행 파일에만 반영합니다.

## MindPlayer에서 시험

시작 화면에는 공통 Jev 선택이 없습니다. Codex 입력줄의 `F6`는 **현재 실행 세션의
ON/OFF 토글**이고 `Enter`가 입력을 전송합니다. Jev 키를 읽었으면 새 세션은 ON으로
시작합니다. 키가 없으면 OFF로 시작합니다. 같은 pane에서 새 thread로 바뀌어도 이 기본값으로
다시 시작합니다. F6로 고른 값은 다음 F6까지 수정·붙여넣기·전송·후속 입력에도 유지됩니다.
OFF는 Jev를 호출하지 않고 실제 네이티브 model/effort를 유지합니다. 전송/큐 수락 당시
선택을 각 UserMessage에 보관하므로 이후 토글이 기존 대기 입력의 선택을 바꾸지 않습니다.
F6로 바꾼 값은 다른 세션이나 앱 재시작에 상속하지 않습니다.

F7 맥락 미리보기와 로컬 previewId 토큰은 제거했습니다. Jev ON의 실제 판단에는
현재 입력과 제한된 같은 세션 판단 상태를 계속 사용하며, 전체 대화 전송이나 민감정보
자동 제거를 보장하지 않습니다. 선택 메타데이터는 로컬 중계에서 소비·제거됩니다.

**Claude Jev 연동은 제거했습니다.** Claude 세션에는 Jev 선택·호출·상태 중계가
없고 기존 네이티브 CLI를 실행합니다. Claude 계정·로그인·설정은 유지합니다.
Kiro/Cursor와 로그인·관리 명령도 기존 경로입니다.
**이미 열려 있는 pane에는 소급 적용되지 않습니다.**

## Codex 네이티브 연동

선택된 계정의 `CODEX_HOME`, 환경변수 제거, 작업 폴더, 원본 입력을 보존합니다.
기존 MindPlayer의 `never + danger-full-access` 권한 정책도 유지합니다.
remote resume가 UI 권한 인수를 거절하므로 이 정책은 app-server 시작 설정에
전달합니다. **아래 별도 실행기의 read-only 기본과 다릅니다.**

중계 모듈은 MindPlayer 바이너리에 포함되며 `~/.mindplayer/runtime/`의 소유자
전용 디렉터리에 완전한 묶음으로 준비됩니다. 저장소 위치나 현재 폴더에 의존하지
않습니다. Node.js 22 이상과 검증된 MindPlayer 전용 Codex v4 설치가 필요합니다.
통합 UI·probe·app-server는 같은 전용 바이너리를 사용하며 전역 Codex는 교체하지 않습니다.
문제가 생기면 오류로 중단하며 중계 없는 실행으로 조용히 우회하지 않습니다.
원래 MindPlayer와 마찬가지로 Ctrl-Q는 pane 표시만 닫고 실행은 유지합니다.
Codex UI의 `/quit` 또는 MindPlayer 종료 시 해당 중계도 정리됩니다.

## MindPlayer 통합의 판정과 모델 적용

통합 경로는 과거 길이/키워드 A/B 규칙을 사용하지 않습니다. 사용자 입력·계정·
작업 폴더·thread·승인 정책은 그대로 두고, 모델과 지원 effort만 선택합니다.
알려진 메인 대화의 새 턴이 대상입니다. 실행 중 새 `turn/start`는 이전 턴 완료 후
판단하며, `turn/steer`와 도구 출력은 네이티브로 통과합니다.
출처가 불확실한 helper는 외부로 보내지 않습니다.

**판정과 모델 변경을 분리합니다.** 전용 `TYPESAFE_API_KEY`는 TypeSafe 직접 API,
`AI_GATEWAY_API_KEY`는 Vercel Gateway에만 사용합니다. 두 키를 혼용하지 않으며,
둘 다 있으면 Gateway 키를 우선합니다. 키가 설정돼 있으면 새 세션은 Jev ON으로
시작하므로, F6로 끄지 않은 프롬프트마다 현재 입력과 제한된 같은 대화의 판단 상태를
해당 서비스로 전송합니다. 키를 설정하는 것이 이 전송에 대한 동의입니다. F6로 끈 세션은
전송하지 않습니다. 모델 비교용 정책 파일이
없어도 입력마다 판정합니다. 명시적으로 외부 전송을 금지한 정책은 존중합니다.

이번 로컬 설치의 키는 저장소 밖 `~/.mindplayer/jev-credentials.json`(소유자 전용
0600)에 저장합니다. 환경변수가 없을 때 이 파일을 읽으므로 새 터미널에서도 사용합니다.
키는 명령 인수·로그에 넣지 않으며 probe/backend/UI와 도구 자식 환경에서 제거합니다.
0600은 다른 OS 사용자의 접근을 막지만 같은 사용자 권한의 임의 파일 읽기까지
격리하는 보안 경계는 아닙니다. 키가 없거나 판단이 실패하면 새 턴을 전송하지 않습니다.

macOS의 Gateway 호출은 시스템 `/usr/bin/curl`의 HTTPS 신뢰 검증을 사용합니다.
관리 인증서를 macOS는 신뢰하지만 Node가 인식하지 못하는 환경을 지원하기 위한
처리이며 인증서·호스트명 검증을 끄지 않습니다. 키와 요청은 stdin으로만 전달하고
명령 인수·로그·임시 파일에 넣지 않습니다. 리다이렉트·자동 재시도는 하지 않습니다.
직접 TypeSafe API와 다른 OS의 전송 경로는 유지합니다. 인증서 오류는 기존 모델줄과
Codex 오류 메시지에서 별도로 식별하며 전송하지 않은 상태를 유지합니다.

각 판정은 전체 요청 32 KiB, 응답 64 KiB, 마감 5초를 기본 상한으로 사용하고,
동일 pane의 중복 pending 요청을 차단합니다. 250ms 요청 간격은 입력을 생략하지 않고
기다립니다. 네트워크 오류·시간 초과는 자동 재호출하지 않습니다. 호출마다 서비스 사용량이
발생하며 이 로컬 간격 제한은 공급자의 서버 측 금액 한도를 대신하지 않습니다.

통합 경로는 **검토된 최신 모델군과 선택 계정의 네이티브 가용 후보를 교차**한
모델+지원 effort 조합만 제공합니다. 2026-10-18 검토 집합은 light `gpt-6-luna`,
standard `gpt-6.1-sol`, frontier `gpt-6-astra`입니다. 카탈로그의 나열 순서나 이름의
숫자 크기를 최신성·역량으로 추정하지 않습니다. 구조화된 세대 정보가 없어 버전 관리된
명시적 집합을 사용하며, 2026-11-18 재검토 기한 또는 알 수 없는 새 기본 모델·업그레이드
대상이 나타나면 전송을 중단합니다. 이는 자동으로 영구 최신을 보장하거나 계정의 실제
추론 성공·이용 권한을 증명하는 목록이 아닙니다.

별도 정책 파일이 없으면 이 후보의 **Jev Choice**를 사용합니다.
모델·effort 설명을 근거로 작업 난이도에 충분한 역량을 고르는 휴리스틱이며,
품질 평가 수치나 측정된 절감률은 만들지 않습니다. 같은 계정·제공자와 정확한
baseline을 검증하며 숨김·접근 거부 후보와 자동 위임을 새로 켜는 `ultra`는 제외합니다.

0.55.14의 `rubric.mjs`는 후보 선택 질문에만 공식 API 참고 단가를 추가합니다.
정확한 후보 ID와 일치하는 가격만 한 번 제공하며, `jev.mjs`가 매 호출마다 유효
기간을 확인합니다. 입력·출력·캐시 단위를 USD/백만 토큰으로 명시하고 OpenAI의
272,000 초과 입력 가격을 별도로 둡니다. 전체
네이티브 입력 길이는 잘린 판단 입력에서 유추하지 않습니다. 충분한 역량과 네이티브
제약이 먼저이며, 단가는 보조 정보입니다. 가격 누락·만료는 미상이고 모델 권한을
늘리거나 c0 보수적 기준·품질 정책을 우회하지 않습니다. 구독 쿼터·실제 청구액이나
effort별 고정 가격·예상 실행 비용을 주장하지 않습니다. 확인일 2026-10-18,
만료일(미포함) 2026-11-18; [OpenAI 가격](https://developers.openai.com/api/docs/pricing).

기존 모델이 확인된 구세대이면 정확히 같은 effort의 현재 frontier를 검증된 fallback
`c0`로 사용합니다. 실제 입력 baseline은 별도로 보존합니다. 이 보수적 정책이 측정된
품질 비열등을 뜻하지는 않습니다. 알 수 없는 모델, 가용하지 않은 baseline, 지원되지
않는 effort는 추측해 복구하지 않습니다. 모호한 문맥·잘림·첨부도 Jev 판단은 수행하되
검증된 현재 fallback을 유지하며, 구세대 fallback으로 돌아가지 않습니다. 경험적
정책과 구세대 baseline이 충돌하면 품질·비용 증거를 만들어내지 않고 전송 전 오류입니다.

판단 기준은 `rubric.mjs`의 `mindplayer-capacity-v2`로 버전 관리합니다. 해결 공간,
여러 단계의 조정 부담, 실패 영향, 후속 작업의 연속성, 정보 부족을 비교하며, 설계·한 줄
수정·개발 후 PR·배포·daily report·장애 분석의 차이를 질문에 함께 제공합니다.
모델 등급을 코드로 미리 찍지 않습니다. 후보 선택 질문은 다른 질문의 답을 읽을 수
없으므로 그 질문 자체에 전체 기준을 포함합니다.

기본 카탈로그 경로는 **현재 프롬프트 + 직전 수락된 같은 세션 판단**만 보냅니다.
대화 원문과 과거 첨부를 보내거나 resume 시 전체 히스토리를 paging하지 않습니다.
스냅샷 전체는 8 KiB로 제한하며 `contextKnown:false`는 과거 대화를 모른다는 뜻입니다.
독립적으로 이해되는 새 요청까지 막는 조건은 아닙니다. 직전 상태는 설정·요구 역량·영향
판단과 네이티브 턴 결과만 포함하고, 원인·작업 완료 사실을 만들어내지 않습니다.
네이티브 `turn/start` 수락 전이나 실패한 선택은 저장하지 않습니다. compact 뒤에는
수락된 판단만 유지하고, 계정·세션 소유권·카탈로그·정책·기준 버전이 달라지면 재사용하지
않습니다. 앱 재시작이나 새 연결에서 상태가 없으면 `null`로 보내고 추측하지 않습니다.
짧은 “계속해”만으로 하향 선택을 정당화하지 않으며, 명확한 새 지시는 과거 판단보다 우선합니다.

실측 Gateway 및 TypeSafe 직접 응답에서 모델 후보 분포가 소수 둘째 자리로 반올림되어 합계가
0.99 또는 1.01이 되는 경우를 처리합니다. 각 값이 실제로 0.01 단위이고, 반올림
구간 안에 합계 1인 분포가 존재하며, 그 구간 전체에서 선택된 후보의 단독 1위가
보장될 때만 허용합니다. 받은 확률을 재정규화하지 않습니다. 작업 역량·품질 정책의
확률 검증과 직접 TypeSafe 응답 검증은 기존의 엄격한 기준을 유지합니다.

프로필·임계값 JSON 계약은 `policy.mjs`의 JSDoc에 있습니다. `policy.test.mjs`의
수치는 합성 테스트 전용이며 실제 정책으로 복사하면 안 됩니다. 별도로
`~/.mindplayer/jev-policy.json`(소유자 전용 일반 파일, 최대 128 KiB)이 있으면
경험적 품질·비용 정책을 우선하고 잘못된 파일을 휴리스틱으로 우회하지 않습니다.
**이 경험적 정책의 현재 native
어댑터는 턴별 전체 문맥/도구 요구를 아직 검증하지 못하므로 근거 없는 자동 전환은
하지 않습니다. 이것이 Jev 판정을 막지는 않습니다.** `requirementsForTurn` 경계는 준비됐고 합성 시험에서만 근거를
주입합니다. 정적 정책 파일의 token 수는 새 턴의 측정으로 인정하지 않습니다.
모르면 `contextTokens`를 생략하고 프롬프트 길이/직전 사용량으로 추정하지 않습니다.
명시적 경험적 정책 경로에만 같은 대화의 사용자/최종 응답을 최대 4쌍, 전체 스냅샷
16 KiB로 제한해 전달하는 기존 계약을 유지합니다. 기본 카탈로그 경로의 새 판단 상태로
이 정책을 우회하지 않습니다. 잘림·현재 첨부·참조 부족은 baseline을 유지하는 사유입니다.

현재 모델도 가용하지 않으면 전송 전 오류입니다. Jev 실패는 미전송 오류이며,
backend 송신 후 결과 불명은 자동 재전송하지 않습니다.

0.57.5는 같은 연결의 계정·제공자 범위에서 실제 사용자 턴의 요청 모델과 실패를
연결합니다. 최종 실패의 `serverOverloaded`만 해당 모델의 모든 effort를 60초간
Jev 후보에서 제외하며, 다음 명시적 사용자 입력 때 나머지 후보 중에서 다시 판단합니다.
중복 완료 알림은 제외 시간을 늘리지 않습니다. 서버 자체 재시도 중인 오류,
인증·사용량·네트워크 오류나 관계없는 서브에이전트 실패로 모델을 차단하지 않습니다.
서버가 명시적으로 모델을 바꾼 경우 검증된 변경 연결의 마지막 모델에 귀속하고,
귀속이 불분명하면 추측하지 않습니다. 새 연결·계정 변경에는 차단 이력을 넘기지 않습니다.

입력 baseline은 그대로 보존하되 혼잡한 baseline을 fallback으로 다시 보내지 않습니다.
남은 메뉴의 첫 항목도 안전한 fallback으로 간주하지 않습니다. 복구 메뉴에는
`abstain`(적합한 후보를 확인하지 못함)을 명시적으로 제공하며, 이 선택·명백한 문맥 부족·
판단 불명·잘림·첨부나 후보 부재에는 전송 전 중단합니다. 경험적 품질 정책의 baseline이 막혔을 때도
정책을 우회하지 않습니다. 실패 작업 자동 재전송, 계정 전환, Jev OFF의 모델 자동 변경은
하지 않습니다. 이 제외는 일시적 실패 관찰이지 실제 서비스 수용량이나 대체 모델 품질 보장이 아닙니다.

품질 비열등·구독 소모 절감·실제 Gateway 과금은 아직 검증하지 않았습니다.
TypeSafe 직접 API의 인증·TLS·응답은 실제 호출로 검증하며 달러 비용은 응답에 없으면 미상입니다.
queued 새 턴의 네이티브 UI 경계도 추가 E2E 검증이 필요합니다.

## 별도 실행기로 시험 (기존 A/B 규칙 하네스)

Node.js 22 이상과 `--remote` 지원 Codex가 필요합니다. 개발 환경에서 확인한
버전은 Node 23.9.0 / Codex 0.162.1입니다. 추가 패키지 설치는 없습니다.
MindPlayer 저장소에서 실제 터미널로 실행하세요.

```sh
node tools/local-model-router/run.mjs
```

새 대화는 현재 작업 디렉터리를 대상으로 **read-only + on-request 승인**으로 시작합니다.
기존 `CODEX_HOME`과 Codex 로그인 환경을 상속하며 인증 파일·설정을 수정하지
않습니다. 다른 작업 폴더/기존 대화를 시험할 때만 다음을 사용합니다.

```sh
node tools/local-model-router/run.mjs --cwd /absolute/path/to/fixture
node tools/local-model-router/run.mjs --cwd /absolute/path/to/fixture --resume THREAD_ID
node tools/local-model-router/run.mjs --list-models
```

`--resume`은 이미 종료한 테스트 대화에만 쓰세요. 설치된 CLI는 remote 재개 시
권한 덮어쓰기를 거절하므로, 재개에는 위 read-only 기본을 적용하지 않습니다.
기존 대화/서버의 권한 설정을 사용하며 `/status`로 실제 권한을 확인해야 합니다.
새 대화의 ReadOnly 표시는 실제 UI에서 확인했습니다.

MindPlayer에서 분리된 계정을 쓰려면 `--codex-home /absolute/path/to/account-home`
을 추가할 수 있습니다. 로그인 정보나 API 키를 인수로 넣지 마세요.

**로컬 전용은 중계 서비스의 공개 범위입니다.** 127.0.0.1의 임의 포트에만
바인딩하고 매 실행마다 만든 bearer token을 자식 UI의 환경변수로 전달합니다.
Origin이 있는 브라우저 연결, 인증 없는 연결, 두 번째 동시 UI 연결은 거절합니다.
Codex 모델 호출 자체는 기존 Codex의 외부 서비스/사용량을 이용합니다.

## 별도 실행기의 실험 규칙 (MindPlayer 통합에는 미적용)

- 새 턴의 프롬프트가 400자 초과이거나 설계·분석·원인·비교·리팩터 등의 단어가
  있으면 B, 나머지는 A를 사용합니다. **Jev나 모델 성능 평가가 아닙니다.**
- 기본 A는 현재 목록의 기본 텍스트 모델, B는 그다음 서로 다른 공개 텍스트
  모델입니다. 목록 순서가 성능/가격/권한을 증명하지 않습니다. 실제 성공한
  호출로 접근 가능성을 별도로 확인해야 합니다.
- 재현 가능한 특정 두 후보가 필요하면 실행 인수 `--simple-model MODEL_A
  --complex-model MODEL_B`로 고정할 수 있습니다. 이는 실험 설정이며 MindPlayer
  화면에 모델 선택기나 자동/수동 버튼을 추가하는 것이 아닙니다.
- `turn/start.model`과 존재할 경우 `collaborationMode.settings.model`을 함께
  바꿉니다. 해당 모델이 광고한 reasoning effort로 맞추고, 프롬프트·대화 ID·
  승인/샌드박스·developer instructions는 보존합니다.
- 실행 중인 턴의 추가 입력(`turn/steer` 포함), 도구 결과는 재선택하지 않습니다.
- 선택 실패/타임아웃은 오류로 중단합니다. 기존 모델로 조용히 우회하지 않습니다.
  전송 후 실패나 연결 단절도 다른 모델로 자동 재시도하지 않습니다.
- 선택 중 연결 종료는 늦은 결과를 폐기합니다. `turn/interrupt`는 실제 turn ID가
  필요하므로 전송 전의 임의 ID로 선택을 취소하지 않습니다. start 응답 대기 중
  interrupt는 실제 ID와 일치할 때만 원문 그대로 전달하며, 가짜 성공은 만들지
  않습니다. 중복 RPC ID/동시 pending start는 차단합니다.
- 승인 요청과 승인 응답은 양방향 그대로 전달합니다. 자동 승인은 없습니다.

## 증거와 한계

실행 시 출력하는 임시 `routing.jsonl`은 소유자만 읽을 수 있습니다. 모델 선택
이유·thread/turn ID·시작 확인·완료 상태를 저장하지만 프롬프트·답변·인증 값은
저장하지 않습니다. Codex 자체는 원래 정책대로 대화 기록을 저장할 수 있습니다.

`route-requested`는 요청, `start-acknowledged`는 시작 응답입니다. 어느 쪽도
그 자체로 실제 제공 모델 증명이 아닙니다. 서버가 내보낸 reroute 알림은 별도로
기록하고, 완료 상태와 함께 판단합니다. `model/verification`은 접근 검증 관련
알림이지 응답 모델 ID 증명이 아닙니다. 서버가 실행 모델 ID를 제공하지 않으면
그 증거 부족을 남깁니다.

`jev-started`/`jev-judged`/`jev-failed`는 thread/request ID별 실제 판정 시도·성공·실패이고,
`model-selected`는 그 판정 뒤 적용한 모델과 유지/변경 사유입니다. 카탈로그 Choice는
모델 설명에 따른 선택이며, 프로필 기반 정책은 비교 근거가 미상이면 baseline을
유지합니다. 어느 경로도 비용 미상을 검증된 최적 모델이나 절감으로 표시하지 않습니다.

0.55.9부터 기존 모델줄에 판단 중 → 선택·요청 중 → 요청 수락 → 실행 중 →
턴 완료/중단/실패를 표시합니다. 시작 응답은 수락만 의미하며, `turn/started`가
실행 중을 설정합니다. 정상 실행에 reroute 알림을 요구하지 않고, 서버 모델 변경
보고는 선택값 옆의 별도 부가 정보로 표시합니다. 요청 모델·effort는 서빙 영수증이
아닙니다. 늦은 시작 응답이 실행·완료를 되돌리거나 이전 턴이 새 판단을 덮지 못합니다.
pane 상태 계약 v2는 `executionVerified` 대신 `serverModelReported`를 사용합니다.
네이티브 모델줄을 안전하게 찾을 수 없는 메뉴·좁은 창 등에서는 기존 창 테두리를
사용하며 터미널 내용·입력·크기를 변경하지 않습니다. 원본 Codex의 모델 표시를
실행 영수증으로 간주하지 않습니다. 같은 대화를
다른 Codex UI에서 동시에 소유하지 마세요. 재개 시험은 원래 실행을 종료한
별도 테스트 대화를 사용하세요.

Codex의 app-server/remote transport는 실험적 인터페이스입니다. 작은 WebSocket
구현은 RFC6455의 텍스트 JSON-RPC에 필요한 범위만 지원하며, localhost 밖으로
노출하거나 운영 서버로 사용하지 마세요. WebSocket 압축/바이너리는 지원하지
않습니다.

실제 설치 환경의 `plugin/list` 응답은 약 15MB였습니다. 프레임/JSONL 메시지는
64MiB로 제한하면서 이 시작 데이터를 통과시킵니다. 이는 크기/메모리의 실험용
상한이지 무제한 첨부 지원이 아닙니다. Codex UI의 자동 제목 생성 등 보조 턴도
중계를 지나지만 통합 정책은 출처를 확인하지 못하면 입력을 Jev로 보내지 않습니다.
Codex 자체의 보조 호출 사용량은 별개입니다.

## 검증

```sh
node --test --test-concurrency=1 tools/local-model-router/*.test.mjs
node tools/local-model-router/run.mjs --list-models
```

테스트는 WebSocket 프레이밍/인증/로컬 제한, 승인 메시지, 원문 보존, 모델 필드,
취소 경쟁, 중복/재전송 방지를 검증합니다. 단위 테스트만으로 실제 Codex UI와
모델 호출이 동작했다고 주장하지 않습니다. 실제 호출 검증은 Codex 사용량을
소비하며, 개인 작업물 대신 임시 테스트 폴더를 사용합니다.

2026-10-15 로컬 검증: 자동 테스트 43개 통과. 원본 Codex UI에서 같은 테스트
대화의 A/B 요청, 한글 여러 줄 입력, 이전 턴의 nonce 기억, 스트리밍, 재개를
확인했습니다. 최종 JSONL 수신기를 적용한 UI에서도 약 15MB 시작 응답과
후속 B/A 모델 요청이 연결 종료 없이 통과했으며, Esc 취소는 서버의
`interrupted` 완료 알림과 화면에서 확인했습니다. 실제 도구 승인은 회귀 테스트로
검증했으며 개인 작업 파일을 수정하는 실호출은 하지 않았습니다.

MindPlayer 0.55.3 통합 검증에서는 설치된 실행 파일에서 기존 테스트 세션을
Enter로 열었습니다. 같은 thread에서 B → A 요청이 각각 완료되고 이전 nonce가
유지됐습니다. Node 테스트 53개, Rust 전체 회귀 테스트와 실제 중계 프로토콜
smoke가 통과했습니다. 계정 선택·새 세션·handoff의 기존 UI 회귀도 포함합니다.
병렬 부하에서 기존 quota 타임아웃 테스트가 흔들려 최종 Rust 검증은
`--test-threads=2`로 실행했습니다. 자세한 설치 경로·체크섬·복구본·실호출 증거는
`mindplayer-integration.validation.json`에 기록합니다.

## 선택 근거

| 대안 | 판단 |
|---|---|
| PTY 키 입력 가로채기 | 원본 화면은 유지하지만 Enter/승인/멀티라인 구분이 취약해 제외 |
| 새 웹 채팅 UI + app-server | 별도 UI는 검증하지만 원본 터미널 유지 여부를 증명하지 못해 제외 |
| 원본 `codex --remote` + 프로토콜 중계 | 이번 실험 대상인 실제 터미널 입출력 경계를 직접 시험하므로 선택 |

MindPlayer 연결 위치도 세 가지를 비교했습니다. 저장소의 절대 경로를 고정하는
방식은 설치 후 이동에 취약하고, 전역 `codex` 래퍼는 MindPlayer 밖의 실행까지
바꾸므로 제외했습니다. 실제 PTY 실행 경계에서 바이너리에 포함된 실행기를
호출하는 방식을 선택해 기존 입력창과 다른 provider의 실행은 유지했습니다.
