01 / RESPONSIBILITY

Jev의 일은 선택이지, 실행 계획이 아니다

MINDPLAYER

시작과 계정·PTY 소유

시작할 때 Native / Jev를 한 번 선택합니다. 새 세션·재개·handoff는 이 실행의 선택을 상속합니다. 계정 홈과 원래 CLI 인수, 터미널 입력·권한 흐름을 유지합니다.

JEV

제공된 후보에서 한 쌍 선택

현재 입력의 제한된 스냅샷과 후보 설명을 받아 model + effort를 고릅니다. Codex와 Claude 중 어느 것을 쓸지 정하거나, 명령 실행·배포 권한을 부여하지 않습니다.

NATIVE PROVIDER CLI

모델 요청과 실제 작업

선택 결과를 네이티브 요청에 반영한 뒤 기존 CLI가 도구·승인·응답을 처리합니다. Jev 판단 API 호출과 Codex/Claude 본 작업의 추론 호출은 서로 다른 요청입니다.

Native 선택 시: 라우터를 우회하며 Jev 키·Node·라우터 상태 채널을 요구하지 않습니다. 실행 중인 기존 pane의 모드를 몰래 바꾸지 않고, 선택을 다음 실행에 저장하지 않습니다.

근거: startup_routing.rs:1–137 · local_router.rs:449–497

02 / TWO EXECUTION PATHS

같은 판단 API, 서로 다른 적용 지점

아래는 프로세스·요청 연결도입니다. 웹 화면이나 새 터미널 UI를 제안하는 그림이 아닙니다.

MindPlayer 시작 선택 → 원래 provider·계정·작업 폴더를 보존 → local_router.rsJev 선택 동의 + 로컬 준비 확인 · 바이너리에 포함된 19개 자산을 비공개 runtime 디렉터리로 추출
CODEX / PROTOCOL PROXY

새 턴 요청을 보내기 직전에 변경

① run.mjs → private-ui.mjs / launch.mjs호환되는 전용 Codex UI와 원래 실행 인수 준비
② 네이티브 UI ↔ proxy.mjs ↔ app-server.mjs로컬 인증 WebSocket / 네이티브 JSONL 연결
③ router.mjs → JevService.decide()소유한 새 turn/start만 판단 · 현재 catalog와 정책 검사
④ router.mjs → 네이티브 turn/startmodel·effort·collaboration 설정을 함께 반영 · 취소·stale 결과 차단

실행 중 입력을 조정하는 turn/steer는 새 턴으로 오인하지 않습니다. 통합 경로의 판단 실패는 해당 새 턴 전송을 차단합니다.

CLAUDE / SESSION-LOCAL MOD

첫 네이티브 추론 step에서 변경

① claude-run.mjs버전 검사 → 비공개 임시 플러그인 → 세션 한정 --plugin-dir
② claude-mod.mjs → claude-broker.mjs메인 turn.start의 실제 turnId 소유 · 첫 turn.step에서 로컬 /judge
③ claude-broker.mjs → ClaudeJevPolicy.decide()requestId + sessionId + turnId 검사 · 현재 후보 메뉴 판단
④ claude-mod.mjs → next({...e, model, effort})같은 턴의 후속 step은 같은 결정 사용 · 새 메인 턴은 새 판단

부모 launcher만 실제 Jev 키를 소유합니다. Claude 자식에는 로컬 broker 주소·임시 토큰만 전달합니다.

기본 공유 판단 계층　rubric.mjs → jev.mjs → Vercel Gateway 또는 TypeSafe 직접 API → 응답 스키마·확률·후보 검증. macOS Gateway 경로는 system-fetch.mjs의 OS 신뢰 저장소 경로를 사용합니다. Codex의 명시적 실측 정책 분기는 policy.mjs의 별도 bounded snapshot을 사용합니다.

두 경로의 보장은 같지 않습니다. Claude 확장이 관측한 Jev 오류는 next()를 호출하지 않아 요청을 막습니다. 하지만 확장 자체가 로드되지 않거나 충돌·시간 제한으로 우회되면 Claude의 기본 실행이 계속될 수 있습니다. Claude 전체를 엄격한 fail-closed 프록시라고 부르면 안 됩니다.

03 / CURRENT FAMILY + TASK DEMAND

“최신 모델군 안에서 난이도별 선택”의 실제 의미

Codex 검토 목록

current-family.mjs:24–37 · 네이티브 0.162.1 catalog 근거

light → gpt-6-lunastandard → gpt-6.1-solfrontier → gpt-6-astra

이 목록과 실제 네이티브 후보의 교집합만 사용합니다. 숨김·접근 거부·모달리티·effort·만료·계정 바인딩 조건을 통과해야 합니다.

Claude 검토 목록

claude-policy.mjs:17–39, 52–74 · 명시적 descriptor 정책

light → claude-haiku-5-5standard → claude-sonnet-5-5frontier → claude-opus-5-5

일반 Opus/Sonnet/Haiku 5.5 세션은 low / medium / high / xhigh / max와 조합한 15개 후보입니다. 입력 네이티브 baseline이 정확히 claude-mythos-5-1일 때만 specialized Mythos 5.1을 포함한 20개 후보를 제공하고, 원래 model/effort를 c0로 보존합니다. 일반 세션에는 Mythos를 추가하지 않으며 Fable로 대체하지 않습니다.

Mythos는 조직 검증이 필요한 모델입니다. 이 정책은 live catalog·entitlement 조회가 아니며, 네이티브의 다섯 effort 수용·실제 적용은 확인되지 않았습니다.

두 레지스트리 모두 2026-10-18 검토, 재검토 기한 2026-11-18T00:00:00Z. 날짜·모델명 숫자 정렬·catalog 앞 순서로 “최신”을 추측하지 않습니다.

  1. 먼저 안전한 메뉴를 만듭니다. 현재 baseline과 effort를 검증합니다. 명시적으로 아는 구형 baseline은 current frontier + 같은 유효 effort로 이행할 수 있지만, 알 수 없는 모델·default·지원 불명 effort를 임의 해석하지 않습니다.
  2. Jev가 입력과 후보 설명을 비교합니다. 해법의 불확실성, 연결된 작업의 조정 부담, 실패 영향, 작업 연속성, 빠진 문맥을 평가합니다. 짧은 후속 질문이나 문서 작업도 어려운 일일 수 있습니다.
  3. 기본 descriptor 경로는 정확한 후보 쌍만 수용합니다. c0…cN은 순위가 아닌 요청 내 식별자입니다. c0는 검증된 안전 기준이며, 실제 들어온 baseline과 다를 수 있습니다. Codex의 명시적 실측 정책 분기는 Jev의 capability 판단을 받은 뒤 chooseConfiguration()이 평가 정책으로 쌍을 고릅니다. 두 분기 모두 정책·문맥·취소 상태를 다시 검사한 뒤 반영합니다.

하드코딩의 구분: 모델군 ID는 의도적으로 검토된 allowlist입니다. 반면 “쉬우면 무조건 Haiku/Luna, 어려우면 무조건 Opus/Astra”라는 고정 매핑은 통합 선택 로직이 아닙니다. router.mjs의 키워드 기반 ruleDecision()은 별도 standalone A/B 실험용이며 MindPlayer 통합은 JevService를 사용합니다.

외부 정책 파일이 있으면 Codex는 평가·품질·비용·가용성 제약을 존중합니다. Claude의 제한된 adapter는 그 평가 정책을 구현하지 않았으므로 claude-policy-unsupported로 차단하며 조용히 무시하지 않습니다. 이 설계만으로 비용 절감이나 품질 동등성이 증명되지는 않습니다.

0.55.14 API 가격 참고의 범위

rubric.mjs:31–67의 buildConfigurationInstructions()는 검증된 제공 후보의 exact model ID만 중복 제거해 API_PRICE_REFERENCE를 만듭니다. 검증일은 2026-10-18, 유효 구간은 2026-10-18T00:00:00Z 이상·2026-11-18T00:00:00Z 미만입니다. 매 요청에 기한을 확인하며, 미확인 ID는 unknown, 만료·유효 구간 밖이면 가격 참조 없이 기존 지침을 사용합니다.

단위는 100만 토큰당 USD, 기준은 first-party Standard/global text API입니다. input/output/cache 요율을 구분하고 Claude cache 쓰기 5분·1시간을 명시합니다. GPT는 prompt 272,000 이하 / 272,001 이상, Haiku는 100,000 이하 / 100,001 이상 조건을 보존합니다. 전체 네이티브 토큰 수·cache 구성·청구 체계가 없으므로 8KiB state로 요금 구간이나 예상 실행 달러액을 계산하지 않습니다. Batch·Fast·도구 요금·지역/공급자 할증은 포함하지 않으며 구독 쿼터 절감을 뜻하지 않습니다.

코드에 기록된 가격 출처: https://developers.openai.com/api/docs/pricing · https://platform.claude.com/docs/en/about-claude/pricing · https://platform.claude.com/docs/en/models/mythos-5-1/overview. 품질·네이티브 요구가 우선이며, 가격은 충분한 후보 사이의 보조 비교 자료입니다.

      if (this.service && !(supported.includes(wanted) || (wanted === null && supported.length === 0 && candidate.defaultReasoningEffort === null))) throw new Error('Selected effort is not supported');
      const effort = supported.includes(wanted) ? wanted : candidate.defaultReasoningEffort;
      if (effort || (this.service && effort === null)) params.effort = effort;
      else delete params.effort;
      if (params.collaborationMode?.settings) {
        params.collaborationMode.settings.model = candidate.model;
        params.collaborationMode.settings.reasoning_effort = effort ?? null;
      }
