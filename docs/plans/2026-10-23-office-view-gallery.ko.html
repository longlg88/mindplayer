세션이 동료가 되어 거점에서 일합니다.

MindPlayer가 연 읽기 전용 브라우저 창입니다. 세션 하나가 거점의 동료 하나입니다. 동료는 마지막 도구에 맞는 작업장을 스스로 찾아가 일합니다. 작업장마다 바닥이 다릅니다: 자료 밭은 흙, 채석장은 자갈, 작업대는 널빤지, 단말 광장은 돌, 보관함은 나무 덱, 먹이통은 꽃밭, 짚 침대는 짚입니다. 끝나면 납품 자리에 서고, 쉴 때는 먹이통에서 먹고, 마지막 프롬프트 뒤 10분이 지나면 짚 침대에서 잡니다. 종료하면 거점 단말 앞에 서서 마지막 화면을 보관합니다. 오른쪽 동료 현황 목록이 동료마다 상태를 한 문장으로 말합니다. 지형은 날짜로 정합니다. 날짜 시드의 난수가 5개 지형 중 하나를 고르고, 나무와 바위 후보의 일부를 날마다 다르게 뺍니다. 탭은 다른 지형을 미리 보는 용도입니다. 거점 배치, 동료, 상태 규칙, 칩, 대기열, 카드는 날마다 같습니다. 동료는 MindPlayer 고유 종(walker.rs)입니다.

5개 시안 공통: 화면 요소와 MindPlayer 데이터

화면 요소보여 주는 것출처와 상태
캐릭터동료의 종은 agent입니다. codex는 펭귄, claude는 문어, kiro는 슬라임, cursor는 병아리입니다. 별명은 없습니다. 목도리 색은 category입니다.MindPlayer agent 색(ui.rs agent_tag). claude와 kiro는 ANSI Magenta와 Cyan이어서 비슷한 hex를 씁니다. 디자인은 새로 그렸습니다.
머리 위 기호세션 상태입니다. ! blocked, ● working, ✓ done, ○ idle을 씁니다.SessionStatus와 pane_dot의 기호와 색입니다. 제품에 있습니다.
목도리와 목록 묶음세션의 category입니다. 작업장은 category와 무관합니다.state.category_of와 category 팔레트입니다. 제품에 있습니다.
구역 바닥과 테두리작업장 7곳이 각각 울타리 안의 네모 구역입니다. 바닥이 흙·자갈·널빤지·돌·나무 덱·꽃밭·짚으로 다릅니다. 구역 사이는 잔디 통로 한 칸입니다. 동료는 자기 구역 안에 섭니다. 구역이 차면 통로의 빈 칸에 섭니다.새 배치 규칙입니다. 테스트가 모든 자리가 자기 구역 안에 있는지, 넘칠 때 겹치지 않는지 확인합니다.
날짜 시드 지형오늘 날짜(UTC 일수)의 난수로 5개 지형 중 하나를 고릅니다. 나무·바위 후보의 일부를 날마다 다르게 뺍니다. 탭의 "오늘" 표시가 그 지형입니다.새 규칙입니다. 시드는 날짜(UTC 일수)입니다. 제품에는 날짜 시드가 없습니다.
종료(ended)종료된 세션은 거점 단말 앞에 서서 마지막 화면을 보관합니다. 사라지지 않습니다. 대기열에서 끝남과 같은 순위입니다. 도착하면 25초 동안 한마디 합니다: 8시간 이상이거나 도구 2,000회 이상이면 "휴… 종료", 1시간 미만이면 "신나게 종료!", 그 밖에는 "수고했습니다".status_rank에서 Ended는 Completed와 같은 0순위입니다. 제품은 종료 세션의 마지막 화면을 유지합니다. 한마디 규칙은 새 규칙입니다.
구역 이름표구역 이름표 7개는 고원 위 여백에 높이를 엇갈려 두고 점선 꺾은선으로 구역의 뒤쪽 모서리와 잇습니다. 선을 모두 그린 뒤 상자를 그려서 선이 상자를 덮지 않습니다.참고한 사무실 사양의 배치 규칙입니다. 캔버스 화면 좌표에 그립니다.
머리 위 복잡함context 사용률이 오를수록 머리가 복잡해집니다. 50% 이상 낙서, 65% 이상 머리카락이 서고 땀, 80% 이상 머리 주위를 도는 종이·?·톱니와 김, 90% 이상 소용돌이 눈과 날아가는 종이.Session.context_pct는 kiro만 값이 있습니다(discovery.rs parse_kiro_file·kiro_context_pct). codex·claude·cursor는 새 수집이 필요합니다. 시안의 값은 합성입니다.
압축(compaction)압축 중이면 종이가 머리 위 "요약" 상자로 빨려 들어갑니다. 끝난 뒤에는 "🧹 정리 완료 · 전→후" 말풍선이 뜹니다. 지금까지 압축한 횟수만큼 발 옆에 상자를 쌓습니다.MindPlayer에 압축 횟수 기록은 없습니다. 압축 중 신호는 pane 화면의 "compacting" 글자로 이미 감지합니다(pty.rs). 횟수는 transcript의 compact_boundary 수집이 새로 필요합니다. 시안의 값은 합성입니다.
직급과 연륜도구 사용 횟수가 100 / 500 / 2,000 / 5,000 / 10,000을 넘을 때마다 직급이 오르고 왕관이 커집니다. 근속이 1 / 3 / 7일을 넘으면 흰머리, 수염, 지팡이가 생깁니다.근속은 Session.started_at으로 잴 수 있습니다. 도구 횟수 필드는 없지만 claude·kiro는 이미 읽는 convo_log의 [tool_use] 줄을 세면 됩니다. codex는 parser 확장, cursor는 없습니다. 시안의 값은 합성입니다.
뒤통수화면 위쪽(멀어지는 쪽)으로 걸을 때는 얼굴 대신 뒤통수를 보입니다. 좌우로 걸을 때는 몸을 뒤집습니다.그리기 규칙입니다.
칠판단말 광장 뒤쪽 칠판에 동료 수, 일하는 중, 기다림, "다음 ▶ 누구", 끝남(종료 포함)·쉼, 도감을 적습니다. "다음 ▶"은 N 키·대기열과 같은 함수에서 받습니다.참고한 사무실 사양의 상황판입니다. 값은 이 페이지의 집계입니다.
야생과 포획category가 없는 세션은 목책 밖 들판(지형의 땅)을 돌아다닙니다. MindPlayer에서 그 세션에 category를 붙이면 단말에서 구슬이 날아가고, 동료가 구슬에 들어가 세 번 흔들린 뒤 "포획!"과 함께 문 앞 계단에 나타나 들어옵니다. category를 해제하면 문으로 나가 들판으로 돌아갑니다(방생).state.assign_category·clear_category는 사용자가 TUI에서 하는 동작입니다. 이 창은 category_of의 변화만 읽습니다. 구슬·흔들림은 참고한 게임의 포획 장면 구조에서 가져온 연출이고 디자인은 새로 그렸습니다.
도감종 = agent 4 × 적성 4 = 16종. D 키나 📖 칩으로 패널을 엽니다. 종마다 오늘 본 세션 수 + 기록, 최고 직급, 5마리부터 ★ 보너스. 칠판에 "도감 n/16"을 적습니다.agent는 제품에 있습니다. 적성은 convo_log의 마지막 도구에서 나옵니다(codex는 parser 확장, cursor는 없음). 날짜를 넘는 누적 기록은 새 저장이 필요합니다. 시안의 기록 값은 합성입니다.
카드의 마크다운마지막 답변을 마크다운으로 그립니다. 코드 블록, 표, 중첩 목록, 굵게, 인라인 코드, 링크를 지원합니다. 선택지 줄(1 예 2 아니요)은 주황으로 강조합니다.먼저 이스케이프하고 그다음에 마크다운을 해석합니다. 링크는 글자 옆에 실제 호스트를 보여 줍니다. 외부 아이콘(브랜드 배지)은 외부 요청 금지 조건 때문에 넣지 않습니다.
명패첫 프롬프트 제목입니다.Session.title입니다. 제품에 있습니다.
경과 시간마지막 프롬프트 뒤 시간입니다. 세션이 실행 중이고 agent가 kiro나 cursor이면 now입니다.last_prompt_at입니다. codex와 claude만 값이 있습니다.
먹이통과 짚 침대idle이면 먹이통에서 먹습니다. idle이고 마지막 프롬프트 뒤 10분이 지났으면 짚 침대에서 잡니다. 침대 5개가 다 차면 먹이통에서 쉽니다.새 규칙. 제품에는 잠 규칙이 없습니다. last_prompt_at이 없는 kiro와 cursor는 자지 않습니다. handoff thread 안의 kiro·cursor는 thread의 값을 받으므로 잘 수 있습니다.
작업장(적성)일하는 중이면 마지막 도구에 따라 자료 밭(읽기 = 채집), 채석장(명령 = 채굴), 보관함(외부 도구 = 운반), 작업대(편집 = 수작업)로 갑니다. 끝나면 ✓ 상자를 들고 납품 자리에 섭니다.claude와 kiro는 convo_log에 도구 이름([tool_use 이름])이 있습니다. codex 기록에도 도구 왕복이 있지만 parse_codex_turn이 버리므로 parser 확장이 필요합니다. cursor는 도구 정보가 없어 작업대로 갑니다.
카드의 마지막 답변그 세션의 마지막 답변입니다.convo_log의 turn(claude·codex·kiro). read_turns는 있고, 이를 보여 주는 표면과 [tool_use]·[tool_result] 블록을 거르는 필터가 새로 필요합니다. cursor는 turn이 0개입니다.
handoff 끈handoff로 이어진 세션은 자기 작업장에서 일하는 동료입니다. 부모와 점선으로 이어지고 조금 작게 그립니다. 목록·대기열·카드에 나옵니다.state.handoff_parent입니다. 제품에 있습니다.
동료 현황 목록, 대기열, N오른쪽 목록이 동료마다 상태를 한 문장으로 말합니다. 아래 대기열은 나를 기다리는 동료를 줄 세웁니다. ✓ done과 종료가 먼저, 그다음 ! blocked입니다. 7개가 넘으면 +N으로 줄입니다. N을 누를 때마다 다음 동료로 넘어갑니다.목록의 status_rank에서 done이 blocked보다 앞입니다. 목록은 24시간 기준 그룹을 먼저 나누지만, 이 시안은 그룹을 쓰지 않습니다.

경계

사용자 결정 2026-10-23
  • 이 창은 읽기 전용입니다. 답장, 멈춤, 키 전송 버튼이 없습니다. 답장은 MindPlayer 목록에서 Enter로 pane에 들어가서 합니다.
  • 실시간 연결은 구현하지 않았습니다. 구현하면 MindPlayer가 127.0.0.1에서 읽기 전용 GET으로 상태를 줍니다. MindPlayer가 이 창을 엽니다. 쓰기 API는 없습니다.
  • 참고한 게임의 이름, 고유명사, 몬스터 디자인은 넣지 않습니다. 가져온 것은 구조뿐입니다: 적성에 맞는 작업장을 스스로 찾아가는 동료, 한 줄 상태 목록, 먹이통과 짚 침대, 돌아가는 단말.
  • 팀의 tmux 사무실 사양에서는 읽기 전용에 맞는 것만 가져왔습니다: 바깥 이름표와 꺾은선, context 머리 효과, 압축 표시, 직급·연륜, 뒤통수, 칠판, 종료 한마디, 마크다운 카드, ? 도움말과 j/k 스크롤. 서버, hooks, send-keys, 답장·멈춤·미루기, 지퍼 입, 회의, 책상 끌기, 서랍, 파일 뷰어, 외부 아이콘은 넣지 않습니다.
  • hook 설치, tmux send-keys, 경로를 내주는 파일 서버는 쓰지 않습니다.

  • codex 세션의 방 이동에 필요한 도구 기록 수집을 정해야 합니다.
