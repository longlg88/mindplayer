## Result

- Recovered missing rollout paths without deleting or overwriting existing
  profiles, session histories, credentials, or the newly recreated old home.
- Created 21 file-level compatibility symlinks from missing `codex-2/sessions`
  paths to their originals in `personal-account/sessions`. All queried indexed old
  paths resolve; the final check reported zero missing files.
- Both affected handoff sessions are running in native `codex resume` processes
  under the user's MindPlayer instance, and live `thread/read` succeeds.
- Installed MindPlayer **0.55.2**; future account rename changes only the label,
  never the provider home. Occupied old slot names cannot reuse credentials.

## Evidence and approach

Initial native errors for `01a133af-4dcc-76a1-b72d-963f03ae22b4` (MindPlayer)
and `01a133b5-8e07-7f80-9e53-b69b52490b48` (tower) named missing rollout files
under `codex-2`. Read-only SQLite queries showed those same absolute paths in
`personal-account/state_5.sqlite`; filesystem checks found the originals under the
renamed home. The original rename code moved the entire provider home without
migrating Codex's internal paths.

Three alternatives were compared before modification:

| Approach | Decision |
| --- | --- |
| Rewrite Codex SQLite paths | Rejected: private schema dependence and live writers. |
| Move the whole profile back | Rejected: both homes now contain records and processes may use either. |
| Restore missing file paths with compatibility links; keep homes stable on future rename | Selected: no overwrites or private database mutation required. |

Protocol behavior was cross-checked against the
[official OpenAI App Server documentation](https://developers.openai.com/codex/app-server)
and JSON schemas generated by the installed `codex-cli 0.162.1`. The validation
script never sends `turn/start` or prints transcripts, tokens, or raw identity.
